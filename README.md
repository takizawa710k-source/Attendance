# QR出席管理

QRコード・バーコードで登校と授業の出席を管理するPythonアプリです。
Railwayへの配置は同梱のDockerfileを使います。

## 登校状況メール（日本時間・平日）

- 9時：既存の登校状況メールを送信します。登校登録が0件なら9時のメールは省略します。
- 10時：9時に未登校だった学生がいる場合、対象者全員の「登校済み（登校時刻）」または「10時時点でも未登校」を送信します。9時の登校登録が0件でも対象者を保存します。
- 9時の対象者はDBに保存するため、途中でアプリが再起動しても引き継ぎます。
- 各時刻の00〜09分に新しい報告を作成します。その間ずっと停止していた場合はその回の報告を作成しません。9時の対象者を保存できなかった日は10時の通知も省略します。
- 10時の通知は10:00:00までの登校を使います。送信後の訂正は反映しません。
- 一時的な送信障害は当日中に5分間隔で再試行します。祝日は自動判定しません。

## 設定

詳細は [GMAIL_HTTPS_SETUP.md](GMAIL_HTTPS_SETUP.md) を参照してください。
**10時通知を使うには、このリポジトリのGmailRelay.gsをGoogle Apps Scriptに反映し、ウェブアプリを新バージョンで再デプロイしてください。**

Railwayには `TEACHER_PASSWORD`、`GMAIL_RELAY_URL`、`GMAIL_RELAY_TOKEN` を設定し、既存の `DATA_DIR` と永続Volumeを維持してください。1レプリカ・自動スリープ無効で運用します。
トークンやパスワードはGitHubに登録しません。

## 学生データ

実際の学生名簿・顔写真・出席DBはこのリポジトリに含めません。
既存のRailway Volumeに登録済みの学生情報を使えます。
新規環境では教師画面から学生を登録するか、`students.example.csv`を参考にローカル専用の`students.csv`を用意してください。
Volumeに学生情報がない状態で配置すると、学生は未登録となります。

## ローカル起動

Python 3.13を用意し、次を実行します。

```sh
pip install -r requirements.txt
python app.py
```

## テスト

```sh
python -m unittest discover -s tests -v
```

実メール送信・Railwayへの配置は別途確認が必要です。
